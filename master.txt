# 2. ЦВЕТОВАЯ СИСТЕМА

Используй следующую палитру как основную дизайн-систему:

| Token | HEX | Назначение |
|---|---|---|
| `color-ink` / Almost Black | `#101010` | Основной тёмный фон |
| `color-champagne` | `#E8DCC8` | Основной светлый текст, бумажные поверхности |
| `color-wine` / Wine Red | `#8D172B` | Главный цветовой акцент |
| `color-ivory` | `#F0EDE7` | Светлые редакционные секции |
| `color-steel` | `#77736F` | Вторичный текст и линии |
| `color-plum` | `#302027` | Дополнительная тёмная поверхность |

### Примерное распределение

- 55% — Almost Black и другие тёмные поверхности.
- 20% — Champagne Ivory и Soft Ivory.
- 15% — Wine Red.
- 7% — Steel Grey.
- 3% — Dark Plum.

### Правила использования

- Тёмный фон доминирует, однако секции должны чередоваться по контрасту.
- Не превращай все восемь секций в один сплошной чёрный экран.
- Champagne и Ivory должны иметь тёплый бумажный характер, а не выглядеть как ослепительно белый.
- Wine Red использовать осознанно: типографические акценты, маркеры, активные состояния, билет RSVP.
- Steel Grey нельзя использовать для мелкого текста на чёрном, если контраст становится недостаточным.
- Не добавлять яркие случайные цвета, неон или тяжёлые градиенты.
- Градиенты допустимы только как едва заметный способ мягкого затемнения фотографии для читаемости текста, а не как самостоятельный декор.

Заведи CSS custom properties для всех цветовых токенов. Не дублируй HEX по всему проекту без необходимости.

# 3. ТИПОГРАФИКА

Два основных семейства шрифтов:

**Заголовки:** Bodoni Moda (предпочтительно) или Cormorant Garamond. Начертания Regular и Italic. Использовать для имён, главных заголовков, крупных временных меток и редакционных акцентов.

**Интерфейс и основной текст:** Manrope или Helvetica Neue. Начертания Regular и Medium. Использовать для навигации, подписей, описаний, labels, кнопок и технических индексов.

### Правила

- Не использовать более двух основных семейств.
- Большие заголовки могут быть очень крупными, вплоть до плакатного масштаба.
- Имена пары — один из главных визуальных объектов Hero.
- Для маленьких подписей использовать uppercase и умеренный letter spacing.
- Времена и номера допускают крупные размеры и табличную ширину цифр.
- Длинные тексты должны оставаться читаемыми.
- Не использовать рукописные, каллиграфические и типичные свадебные шрифты.
- Подключить шрифты корректно, предусмотреть fallback.

# 4. ОБЩИЕ ПРАВИЛА ДИЗАЙНА И LAYOUT

- Основная ширина контента: ориентировочно 1180–1320 px.
- Некоторые фото, фоны и типографические полосы могут выходить за пределы контейнера на всю ширину окна.
- Использовать редакционную асимметрию, переменную ширину колонок и выразительный масштаб.
- Чередовать плотные и просторные секции.
- Не делать все блоки одинаковой высоты и структуры.
- Не заворачивать каждый элемент в отдельную card.
- Общие скругления минимальны. Предпочтительны прямые края, тонкие рамки и чёткие прямоугольные плоскости.
- Придерживаться согласованной системы отступов и ширины текста.
- Использовать нумерацию секций `01 / 08`, `02 / 08` и далее.
- Служебные подписи могут быть на английском, основной смысловой текст — на русском. Допускаются английские короткие названия событий как часть арт-дирекции.

## 4.1. Фирменные элементы

1. `PRIVATE EVENT / 001` — индекс события.
2. `ISSUE Nº 001` — редакционная подпись.
3. `CHAPTER 01` … `CHAPTER 08` — номера секций.
4. Marquee-полосы с фразами `A NIGHT TO REMEMBER` и `FOREVER STARTS TONIGHT`.
5. Тонкие правила-разделители.
6. Небольшие временные метки, рамки кадра и event codes.
7. Digital admission pass в RSVP.

Эти элементы должны поддерживать дизайн, а не заполнять каждое свободное место. Не имитировать в избытке интерфейс монтажной программы или техническую панель.

## 4.2. Общая навигация

В Hero разместить минимальную навигацию с якорями:
- STORY → Section 02.
- THE NIGHT → Section 03.
- LOCATION → Section 04.
- RSVP → Section 07.

Навигация должна плавно прокручивать к соответствующим секциям. Предусмотреть заметные hover/focus состояния. На мобильных устройствах навигация должна быть компактной и удобной для касания.

## SECTION 01 — HERO / THE INVITATION

### Назначение

Создать первое сильное впечатление. Hero должен выглядеть как афиша фильма или обложка fashion-журнала, а не как привычный свадебный экран.

### Содержимое

- Имена: Эмилия & Леон / Анастасия & Кирилл.
- Дата: 12 июня 2027 / 12 JUNE 2027.
- Фраза: «Один вечер. Одна история. И люди, с которыми мы хотим её разделить».
- Навигация: STORY / THE NIGHT / LOCATION / RSVP.
- Служебная надпись: `PRIVATE EVENT / 001`.
- Небольшая подсказка прокрутки: `SCROLL TO EXPLORE`.

### Визуал и композиция

- Главная фотография пары занимает большую часть первого экрана.
- Фотография горизонтальная, ориентир 16:9, с возможностью отдельного mobile crop.
- Невеста в молочном архитектурном атласном платье; жених в классическом чёрном смокинге.
- Вечерняя архитектурная локация, выразительный свет, direct flash или мягкий направленный боковой свет.
- Пара располагается немного правее центра; слева сохраняется относительно спокойное пространство под текст.
- Имена набраны крупной антиквой. Разрешено частично перекрывать фотографию, если текст остаётся читаемым.
- Дату и служебные подписи расположить в узких колонках или по краям композиции.
- Сверху может располагаться тонкая строка с event code.
- Избегать декоративных рамок вокруг фотографии.

### Анимация

- Короткий cinematic intro: почти чёрный экран, event code и дата, затем открытие Hero.
- Пролог можно пропустить кликом или клавишей.
- Он не должен блокировать страницу, повторяться после перехода по якорям или задерживать доступ к содержимому.
- Фотография мягко проявляется; допустим медленный zoom 1.00 → 1.035.
- Имена, дата и навигация появляются последовательно.

### Заголовок

«Место, где начнётся наш вечер».

### Название

`MAISON NOIRE`.

### Адрес

«Московская область, загородная резиденция Maison Noire». Указать, что это демонстрационный адрес, если он не заменён подтверждённым.

### Описание

«Пространство с выразительной архитектурой, камерными залами и садом, который после заката становится частью нашего вечера».

### Визуал

- Крупная фотография современной или исторической резиденции с выразительной архитектурой.
- Не использовать типичное фото зелёной усадьбы в духе botanical wedding.
- Предпочтительны тёмный камень, фактурный фасад, большие окна, внутренний зал, архитектурная подсветка.
- Название площадки может накладываться на фотографию крупной антиквой.
- Адрес, информация о прибытии и схема размещаются в отдельной редакционной колонке.

### Авторская карта

Создать адаптивную плоскую карту в SVG или HTML/CSS. Это не спутниковая карта и не скриншот стороннего картографического сервиса.

Стиль карты — минималистичный архитектурный план / wayfinding graphic:
- фон Champagne Ivory или Almost Black в зависимости от секции;
- тонкие линии построек и дорожек;
- условные прямоугольные здания и зоны;
- ограниченная палитра Almost Black, Ivory, Steel Grey и Wine Red;
- три круглых маркера;
- пунктирная линия между маркерами;
- короткая легенда, созданная HTML, а не запечённая в изображении.

Точки:
- `01 — ARRIVAL`.
- `02 — CEREMONY`.
- `03 — DINNER & PARTY`.

Карта должна быть декоративной схемой площадки, а не пытаться изображать точную географию. На мобильном устройстве она адаптируется по ширине и сохраняет читаемость маркеров.

### Анимация

Плавное появление карты, прорисовка пунктирного пути и последовательное появление маркеров. При reduced motion карта отображается статично.

«Будем рады, если вы поддержите настроение вечера в глубоких, благородных оттенках и вечерних силуэтах. Главное — чувствовать себя собой и быть готовыми праздновать».

- Champagne — `#E8DCC8`.
- Ivory — `#F0EDE7`.
- Deep Plum — `#302027`.

Цветовые образцы создавать средствами CSS, а не запекать внутрь изображения.

### Композиция

- Двухколоночный editorial-блок на Desktop.
- Текст и практические рекомендации занимают одну сторону.
- На второй стороне — пять прямоугольных swatches и фотография fashion moodboard.

- Изображение должно быть модным editorial still life, не плоской таблицей образцов.
- Не использовать подписи, буквы или логотипы внутри сгенерированной фотографии.
- На Mobile расположить текст, swatches и изображение последовательно.

### Анимация

Плавное последовательное появление swatches. Hover-эффект — минимальный scale или изменение рамки. Не делать цветные образцы круглыми, если это ослабляет геометричный стиль.

## SECTION 06 — GALLERY / THE MOMENTS

### Заголовок

«Кадры нашей истории».

### Содержимое

Ровно четыре самостоятельные фотографии той же пары, что и на Hero:

1. **gallery-portrait.webp** — уверенный редакционный портрет пары.
2. **gallery-motion.webp** — прогулка или танец, естественное движение, допустим лёгкий motion blur.
3. **gallery-details.webp** — крупный план рук, колец, букета или фактуры свадебного образа.
4. **gallery-candid.webp** — живой эмоциональный момент, пара смеётся или общается.

### Визуальные требования

- Все изображения 4:5.
- Единая цветокоррекция и один визуальный мир.
- Не допускать разной внешности пары между кадрами.
- Не допускать случайного изменения свадебной одежды.
- Сочетать чёрно-белые и цветные кадры можно только если это выглядит как единая арт-дирекция; не менять обработку случайным образом.
- Предпочтительны прямой вспышечный свет, выразительные тени, естественные эмоции и кинематографическая атмосфера.

### Сетка

- Desktop: четыре колонки при достаточной ширине, иначе 2×2.
- Tablet: две колонки.
- Mobile: две колонки, если кадры остаются читаемыми; допустима одна колонка на узких экранах.
- Строго одинаковые пропорции, без хаотичного masonry.
- При желании использовать короткие индексы `FRAME 01`, `FRAME 02` и т.д.

### Lightbox

- Нажатие открывает изображение крупно поверх затемнённого фона.
- Закрытие по кнопке, Escape и клику на фон.
- Поддержать переход между изображениями кнопками и клавиатурой, если это не усложняет реализацию.
- Блокировать скролл страницы при открытом lightbox.
- Доступный `alt`, aria-label и видимые focus-состояния.

## SECTION 07 — RSVP / YOUR PASS

### Заголовок

`YOUR PRESENCE IS REQUESTED` / «Будем рады видеть вас».

### Подзаголовок

«Пожалуйста, подтвердите присутствие до 25 мая 2027 года».

### Форма

1. Имя и фамилия — обязательное текстовое поле.
2. Присутствие — выбор «Да, буду» / «К сожалению, не смогу».
3. Количество гостей — select или number input с разумными значениями. Если выбран отказ, поле может скрываться или становиться неактивным; логика должна быть понятной.
4. Комментарий или пожелания — необязательное textarea.
5. Кнопка `CONFIRM ATTENDANCE` / «Подтвердить присутствие».

### Важное ограничение

Форма является визуальным интерактивным макетом. Не подключать API, базу данных, почту и серверную отправку. Не заявлять пользователю, что ответ реально отправлен или сохранён на сервере.

### Визуальный стиль

- Almost Black или Dark Plum фон.
- Champagne Ivory текст.
- Wine Red акцент.
- Тонкие границы полей.
- Минимум полей, чёткие подписи и состояния.
- Небольшие радиусы или прямые края.
- Кнопка должна иметь hover, focus, active и disabled состояния.
- Форма должна оставаться удобной на мобильном экране.

### Демонстрационное состояние после отправки

После успешной локальной валидации и нажатия кнопки:
- показать короткое подтверждение, что это демонстрационный ответ;
- отобразить digital admission pass;
- включить в билет имя гостя, `AFTER THE VOWS`, дату `12 JUNE 2027`, название `MAISON NOIRE` и статус ответа;
- если пользователь отказался, билет/подтверждение должны честно отражать статус `REGRETS RECEIVED`, а не изображать билет на вход;
- предусмотреть кнопку «Изменить ответ» или возможность вернуться к форме.

Не использовать настоящие QR-коды, которые выглядят как действующие пропуска. Можно создать декоративный кодовый графический элемент, явно являющийся частью визуального оформления.

# 6. ПОДГОТОВКА ИЗОБРАЖЕНИЙ И IMAGE GENERATION BRIEF

## 6.1. Режим работы с изображениями

Не пытайся самостоятельно генерировать фотографии. На этом этапе задача — подготовить полный список визуальных материалов и отдельный файл `IMAGE_GENERATION_BRIEF.md` с индивидуальными промптами, которые можно передать в любой AI Image Generator.

Не подставляй случайные фотографии из интернета и не используй изображения с водяными знаками. Не создавай программные псевдо-фотографии вместо настоящей свадебной съёмки.

Сайт должен быть полностью реализован даже до появления финальных изображений. Подготовь директорию `assets` с понятными названиями, визуальные заглушки, которые явно показывают назначение каждого отсутствующего материала, и автоматическое использование настоящих файлов после их добавления. Заглушки не должны выглядеть как пустые цветные прямоугольники в финальном портфолио: используй аккуратные asset placeholders с подписью для этапа разработки, а при финальной сборке они должны заменяться реальными изображениями.

В `IMAGE_GENERATION_BRIEF.md` обязательно внеси для каждого материала:
1. Номер.
2. Имя файла.
3. Секцию, в которой используется.
4. Точное описание изображения.
5. Соотношение сторон.
6. Рекомендуемое разрешение.
7. Композицию и расположение объектов.
8. Цветовую гамму и обработку.
9. Готовый короткий prompt на английском языке.
10. Negative prompt.
11. Информацию о reference image и непрерывности внешности пары.

Промпты должны быть конкретными и готовыми к копированию. Не использовать общие фразы вроде `beautiful wedding photo` без описания сцены, света, одежды, композиции и стилистики.

## 6.2. Единая внешность пары

Все фотографии с парой должны изображать одних и тех же вымышленных людей:

- **Анастасия / невеста:** взрослая женщина с тёмно-каштановыми волосами, собранными в гладкий низкий пучок; минималистичный макияж; молочное архитектурное атласное свадебное платье без пышного декора.
- **Кирилл / жених:** взрослый мужчина с короткими тёмными волосами; чёрный классический смокинг, белая рубашка, чёрная бабочка.

Сначала создать `hero-couple.webp`. После утверждения Hero использовать его как reference image для всех галерейных кадров, если генератор поддерживает references. Сохранять лица, возрастной образ, волосы, одежду и общую стилистику.

Не генерировать отдельные кадры с разными людьми. Не менять платье и костюм без явно предусмотренной причины.

# 7. SVG И ГРАФИЧЕСКИЕ ЭЛЕМЕНТЫ

Создать векторные элементы самостоятельно, средствами SVG/HTML/CSS. Не использовать растительные мотивы.

# 8. АНИМАЦИИ И ПОВЕДЕНИЕ

Использовать деликатные эффекты, соответствующие кинематографическому и редакционному характеру проекта:

- Fade In.
- Fade Up.
- Stagger.
- Draw SVG Path.
- Slow Zoom.
- Subtle Hover Scale.
- Smooth Scroll.
- Marquee Text.
- Ticket Reveal.

Рекомендуемые ориентиры:
- Появление текста: 450–700 мс.
- Появление секции: 550–750 мс.
- Stagger: 100–160 мс.
- Hero zoom: 1.00 → 1.035.
- Появление карты: около 700–900 мс.
- Прорисовка пути: 1.2–1.7 секунды.
- Hover для фото: до 1.02 за 450–550 мс.
- Reveal билета: 450–650 мс.

Правила:
- Анимации секций запускаются при попадании в область видимости.
- Не запускать тяжёлые бесконечные эффекты.
- Marquee должен останавливаться или становиться статичным при `prefers-reduced-motion`.
- Не использовать мигающие вспышки и стробоскопические эффекты.
- Не блокировать скролл ради длительной заставки.
- При reduced motion показывать контент без задержек и перемещений.
- Избегать layout shift: анимация не должна менять геометрию документа.

# 9. АДАПТИВНОСТЬ

Обязательно создать полноценные версии для Desktop, Tablet и Mobile. Это не просто уменьшение desktop-макета.

## Desktop

- Широкие редакционные композиции.
- Hero с крупным изображением, выразительными именами и свободным пространством.
- Контентная ширина около 1180–1320 px.
- Возможны двух- и четырёхколоночные композиции.
- Галерея — четыре равные колонки, если ширина позволяет.
- Крупные заголовки должны учитывать реальные размеры viewport.

## Tablet

- Сетки перестраиваются на две колонки.
- Навигация остаётся читаемой.
- Фото и подписи не накладываются друг на друга.
- Hero сохраняет визуальную иерархию.

## Mobile

- Самостоятельная вертикальная композиция.
- Hero использует отдельное кадрирование и безопасную зону для имён.
- Заголовки адаптируются через `clamp()` и не выходят за края.
- Навигация компактная, все интерактивные цели удобны для касания.
- Расписание становится вертикальным списком.
- Location-карта перестраивается по ширине и не теряет подписи.
- Dress Code располагает swatches и фото в логичном вертикальном порядке.
- Галерея — две колонки либо одна на очень узком экране.
- RSVP-поля занимают доступную ширину, labels не обрезаются.
- Никакого горизонтального скролла.

Проверить как минимум ширины 1440 px, 1024 px, 768 px, 390 px и 375 px. Дополнительно проверить очень узкий экран около 320–360 px.

# 10. ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ

- Реализовать один длинный сайт с восемью секциями.
- Секции идут в заданном порядке.
- Навигация использует якоря и плавную прокрутку.
- Поддержать корректную работу при выключенном JavaScript там, где это применимо; критический контент не должен зависеть от сложных эффектов.
- RSVP — только демонстрационная клиентская интерактивность.
- Lightbox для четырёх фотографий.
- Адаптивная SVG-карта.
- Все SVG масштабируются чётко.
- Использовать семантический HTML.
- Оптимизировать изображения после их добавления.
- Для изображений ниже первого экрана использовать lazy loading.
- Для Hero не применять lazy loading, если это задерживает главный экран.
- Указывать width/height или aspect-ratio, чтобы предотвратить layout shift.
- Использовать подходящий `object-position` для каждого breakpoint.
- Добавить осмысленные alt-описания.
- Достаточный контраст текста.
- Видимые focus-состояния.
- Поддержать `prefers-reduced-motion`.
- Не подключать базу данных, авторизацию, личный кабинет, платежи, API или серверную обработку RSVP.
- Не добавлять внешние зависимости ради одного простого эффекта, если он может быть реализован CSS/JS.
- Не допускать ошибок консоли и сломанных ссылок.

## 10.1. Состояния и надёжность

Для интерактивных элементов продумать как минимум:
- исходное состояние;
- hover;
- focus-visible;
- active;
- disabled, где применимо;
- ошибку валидации;
- успешное локальное демонстрационное состояние;
- возможность вернуться или повторить действие.

Не показывать success до завершения локальной валидации и обработки действия. В тексте подтверждения явно указать демонстрационный характер формы.

## 10.2. Производительность

- Не использовать тяжёлые видеофоны.
- Не использовать 3D-эффекты.
- Оптимизировать размер фотографий; при наличии исходников подготовить png/AVIF и fallback.
- Lazy-load изображений ниже первого экрана.
- Не анимировать большие blur/filter области на каждом кадре.
- Использовать transform/opacity для анимаций, когда возможно.
- Отключать или упрощать анимации на мобильных устройствах и при reduced motion, если это улучшает производительность.
